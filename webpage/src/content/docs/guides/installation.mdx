title: Installation
description: Install the tools, prepare a cluster with cert-manager, and install the Ignition Helm charts.
---

This guide takes you from an empty workstation to a running Ignition gateway: install `kubectl` and Helm, add cert-manager and an issuer to your cluster, then install a chart.

## Requirements

- A Kubernetes 1.23 or later cluster, with a storage class that can provision persistent volumes. For local development, Docker Desktop (with Kubernetes enabled) or kind work.
- `kubectl` and Helm 3. The repository's CI workflows use Helm v3.22.0.
- cert-manager and an issuer, described in [Prepare the cluster](#prepare-the-cluster). The charts create cert-manager `Certificate` and `Issuer` resources, so they do not install without it.

## Install the tools

### Windows (PowerShell)

```powershell
winget install Kubernetes.kubectl
winget install Helm.Helm
```

### macOS

With [Homebrew](https://brew.sh/):

```bash
brew install kubectl
brew install helm
```

### Linux

These commands assume an x86-64 machine. For other platforms, see the [Kubernetes](https://kubernetes.io/docs/tasks/tools/) and [Helm](https://helm.sh/docs/intro/install/) installation guides.

```bash
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
```

### Check the tools

```bash
kubectl version --client
helm version
```

## Prepare the cluster

### Install cert-manager

The charts use cert-manager to issue the Gateway Network certificates. Install it with Helm. CI tests the charts with cert-manager v1.18.2:

```bash
helm repo add jetstack https://charts.jetstack.io
helm upgrade --install cert-manager jetstack/cert-manager -n cert-manager --create-namespace \
  --version v1.18.2 --set crds.enabled=true --wait
```

See the [cert-manager documentation](https://cert-manager.io/docs/installation/) for other installation methods.

### Create an issuer

Each chart creates a CA certificate for its Gateway Network, signed by the issuer named in `certManager.issuer.name` and `certManager.issuer.kind`. By default that is a `ClusterIssuer` named `cluster-issuer`. Without it, the Gateway Network certificates are not issued and the gateways do not start.

The issuer must be able to sign a CA certificate. A self-signed `ClusterIssuer` is the simplest choice, and is what CI uses. Save this as `issuer.yaml`:

```yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: cluster-issuer
spec:
  selfSigned: {}
```

Apply it:

```bash
kubectl apply -f issuer.yaml
```

To use an existing issuer instead, set `certManager.issuer.name`, and set `certManager.issuer.kind` to `Issuer` if it is a namespaced issuer in the release's namespace.

## Install a chart

### Add the repository

Each chart version is published as a GitHub release, and the Helm repository index is served from this site:

```bash
helm repo add ignition-charts https://apollogeddon.github.io/ignition-helm
helm repo update
```

To see the available versions:

```bash
helm search repo ignition-charts --versions
```

### Failover

Install a single gateway. Set your own admin password; the default is `admin`.

```bash
helm install my-ignition ignition-charts/ignition-failover \
  --set ignition.secrets.GATEWAY_ADMIN_PASSWORD=mysecretpassword
```

Add `--set ignition.redundancy.enabled=true` for a Master/Backup pair.

### Scaleout

Install one backend and one frontend gateway:

```bash
helm install my-scaleout ignition-charts/ignition-scaleout \
  --set backend.secrets.GATEWAY_ADMIN_PASSWORD=mysecretpassword \
  --set frontend.secrets.GATEWAY_ADMIN_PASSWORD=mysecretpassword
```

### Check the installation

The gateways take a few minutes to start. Watch the pods until they are Ready:

```bash
kubectl get pods -w
```

The Services are `NodePort` by default. See the [chart reference](../../charts/failover/) for the Service, Ingress and other options.
